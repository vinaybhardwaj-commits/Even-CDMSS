Scores are deterministic instrument arithmetic (RCRI · mFI-5 · Charlson) over stored inputs — no model contributes a point of score. Ranges mean inputs are missing, not that the engine is unsure of its arithmetic.

  1. 1Worker heartbeat. Day-window cron sweep (readmit posture: sweep-is-the-retry, idempotent on (dedup_key, engine_version)). Stamp shows last completed sweep.
  2. 2Flag state is always visible. PREOP_EXTRACT_ENABLED / PREOP_NARRATIVE_ENABLED ship OFF; the board must render correctly in this state (PRD §7).
  3. 3Degradation is a first-class state (PRD §8). Booking-only patients render ranges + missing lists — thin data is the finding, never hidden.
  4. 4Why-line = top-points factor of the dominant instrument, derived deterministically (SREWS derive.ts pattern).
  5. 5Missing-input line names what would tighten the score and where it comes from — the module's own nudge toward its data gaps.
  6. 6Situation line (red) reserved for operational danger: RED/CRITICAL with no finalized PAC inside 72 h.
  7. 7Mark reviewed is Slice 1's only workflow verb (per-case, per-snapshot-version; a new snapshot version re-opens review). Feeds the needs-review predicate + chooser badge.
  8. 8Range chips are dashed. Tier scores the range's confirmed lower bound, flooring at AMBER when the upper bound crosses a severity boundary (tier rule v0, §3 below) — and the fix it demands is data, which the card itself names.

3 · Tier rule v0 — deterministic, builder implements exactly this

Composite tier = max severity across the three instruments, with two escalations. A range scores as its lower (confirmed) bound; if the upper bound would land a higher severity, the tier floors at AMBER and carries the unconfirmed tag — missing data alone never mints RED (the SREWS flood lesson: creatinine is missing for ~83% at booking), but a boundary-crossing range can never render GREEN either. Calibration review after 4 weeks of live data — thresholds move only by PRD amendment.
